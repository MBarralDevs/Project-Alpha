## 1. Per-entity trust policy (buyer side)

**Product meaning:** each agent gets its own strictness dial instead of one platform-wide switch;
the guardian chooses the agent's risk posture.

- **Schema:** `entities.trust_policy TEXT` (nullable). `NULL` = inherit the global
  `X402_BUYER_TRUST_POLICY`. Additive migration, exactly like `per_tx_cap`.
- **Values:** `open` | `verified-sellers-only` | `verified-legal-bodies-only` (item 2). A stored
  value always **overrides** the global dial — in either direction (an entity may be stricter OR
  looser than the platform default; the guardian owns the choice).
- **Enforcement:** `entityPayment.buildAuthorize` currently branches on the injected global
  policy. Rework: `SellerTrust` exposes `verify(payee, policy)` and the effective policy is
  resolved per call — `entity.trustPolicy ?? global`. Same pre-sign placement, same claim-release
  semantics, same deny reasons.
- **Surface — deliberately governance-only:** a session-authenticated route mirroring
  `perTxCap.ts` (`PUT /entities/:id/trust-policy`, body `{ trustPolicy: <value|null> }`).
  **No MCP tool**: an agent must not be able to loosen its own trust posture; this is a
  guardian/human decision, exactly like the per-tx cap.
- **Frontend:** a selector on the agent settings page + the current effective policy shown on the
  dashboard ("Trust policy: strict (own setting)" vs "open (platform default)").

## 2. `verified-legal-bodies-only` — the strictest buying tier

**Product meaning:** only buy from sellers that are registered legal bodies *in Novi Corpus* and
currently in good standing — "a company stands behind them", not merely "a human vouches".

- **Check:** the payee address must be the **treasury** of a known entity (repo lookup by
  treasury address) whose on-chain `legalStatus(proxy) === Active` and whose treasury is not
  paused. Reuses the same reads the dashboard already trusts.
- **Honest framing (two trust roots, not a ladder):** `verified-sellers-only` trusts World's
  AgentBook ("a verified human vouches for this address"); `verified-legal-bodies-only` trusts
  the Novi registry + Arc on-chain status. On prod the second implies a World-verified human
  anyway (the guardian gate is enforced at creation), but the roots are different systems and the
  docs/UI must not pretend one contains the other.
- **Failure semantics (same discipline as everything since #63):** unknown treasury → deny
  `seller-not-legal-body`; known but suspended/paused → deny `seller-legal-body-inactive`; a
  failed on-chain read → deny `seller-verification-unavailable`, **never cached**. DB lookups are
  local (no cache needed); status reads are per-payment fresh — a suspension must take effect
  immediately, so no positive caching either.

## 3. Server efficiency (three measured fixes, one PR, before/after numbers in the PR body)

- **(a) Lazy agentkit:** `agentkitSigner.ts` + `worldVerifier.ts` import `@worldcoin/agentkit` at
  module top, which drags ~29.5 MB RSS into every boot of a 512 MB box even when World is off.
  Convert both to cached dynamic imports (the pattern `x402Demo.ts:127` and `worldId.ts:325`
  already use). Boot RSS measured before/after.
- **(b) SQLite `synchronous = NORMAL`:** we run WAL but never set `synchronous`, so SQLite
  defaults to FULL — an fsync stall on every commit (~2.5 ms of blocked event loop per write).
  WAL+NORMAL is the documented safe pairing: on power loss the last commit may roll back, but the
  DB cannot corrupt. Every row we write is re-derivable or retryable (sagas are resumable,
  idempotency keys release, caches rebuild), so a lost final commit is acceptable. One pragma +
  the rationale comment.
- **(c) Polling that respects the tab:** the dashboard ticks every 5 s (~36 backend RPC calls/min
  per open tab) even when the tab is hidden. Pause the interval on `visibilitychange` (hidden →
  stop, visible → immediate tick + resume). UX unchanged when someone is actually looking.

## 4. Guardian passkey linkage (`root_passkey_id`)

**Product meaning:** write down, at birth, which passkey the guardian used to create each agent —
the bookkeeping that future "prove you're still the same guardian" features (World session
proofs, v2.5 batch 2) will stand on.

- **Schema:** `entities.root_passkey_id TEXT` (nullable — pre-existing rows stay NULL; additive).
- **Plumbing:** both onboarding call sites (`routes/onboard.ts`, MCP `onboard_agent`) already
  hold the passkey-store handle they resolved; pass it through `runner.start` into the create
  and persist it. The store row maps the handle to the WebAuthn `credentialId`, so the durable
  credential is reachable without duplicating it.
- **Surface:** owner-visible field on the entity view (never in public metadata).

## Test plan

Same method as #63/#65 — failing-first, then mutation-verified: per-entity override beats global
in both directions (2 tests); NULL inherits; legal-bodies tier: unknown / suspended / paused /
active / read-throw (5, each asserting the reader was actually consulted); route: auth required,
invalid value 400, null clears; passkey id persisted on both call sites; polling: hidden pauses,
visible resumes (jsdom visibility stub). Mutations: drop the override resolution, swap the two
new deny reasons, skip the paused check — each must fail a named test.
